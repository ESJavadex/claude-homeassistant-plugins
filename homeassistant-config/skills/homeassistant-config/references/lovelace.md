# Dashboards (Lovelace) Reference, Home Assistant 2026

Covers HA 2024.3 to 2026.11. Items marked **2026.11** come from the beta release
notes (final release 2026-11-04); check them if the user is on 2026.10 or older.

Validate any dashboard, view, card snippet or `.storage/lovelace` file with:

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/lovelace_validator.py" dashboard.yaml [--strict]
```

## Outdated → current

Old examples on forums and in older AI answers are wrong in these ways:

| Outdated | Current | Since |
|---|---|---|
| `action: call-service` + `service:` + `service_data:` | `action: perform-action` + `perform_action:` + `data:` + `target:` | 2024.8 |
| `layout_options: {grid_columns: 2, grid_rows: 1}` | `grid_options: {columns: 6, rows: 1}` (12-column grid, multiply by 3) | 2024.11 |
| View with `cards:` and no `type:` | `type: sections` + `sections:`. `cards:` without type is masonry | 2024.11 default |
| Section `title:` | First card of the section is `type: heading` | 2024.10 |
| Badges as bare strings or with `display_type:` | `type: entity` + `show_name` / `show_state` / `show_icon` / `state_content` | 2024.8 / 2024.9 |
| `conditional` card or stacks only to hide or group cards | `visibility:` on the card/badge/section; grid sections for grouping | 2024.6 |
| Heading card `entities:` | Heading card `badges:` | late 2024 |
| Area card `show_camera`, `navigation_path` | `display_type: camera`, `tap_action: {action: navigate, ...}`, `area-controls` feature | 2025.7 |
| `state_color: true` | `color: state` (or a color name / hex) | 2025.11+ |
| Logbook card `entities:` | Logbook card `target:` | 2025.1 |
| Top-level `lovelace: mode: yaml` | `lovelace: resource_mode: yaml` + `dashboards: lovelace: {mode: yaml, filename: ...}` | 2026.2 |
| `iframe_panel:` in configuration.yaml | Webpage dashboard (Settings > Dashboards) | 2024.4 |
| `--paper-*` theme variables | `--ha-*` tokens (`--ha-font-*`, `--ha-line-height-*`, ...) | 2025.5 (removed) |
| Custom card for sliders, chips, thermostat, graphs | Tile features, badges, heading, shortcut, clock, distribution cards | 2024-2026 |
| Relying on `friendly_name` for card labels | `name:` (string or name objects); unnamed cards show "Device Entity" | 2026.11 |
| Only state/numeric_state/screen/user/and/or conditions | Also `not`, `time`, `location`, `attribute:`, and automation conditions | 2025-2026.10 |
| HACS as a separate install | Built-in Marketplace (Settings > Marketplace) | 2026.11 |

## Where dashboards live

- **UI dashboards** (default): stored in `/config/.storage/lovelace` (main) and
  `/config/.storage/lovelace.<dashboard_id>`. Edit them in the UI or with
  Edit dashboard > three dots > Raw configuration editor. Do not hand-edit the
  `.storage` files while HA is running.
- **YAML dashboards**: a file you register in `configuration.yaml` (below). The
  UI editor is read-only for them; after editing, use the dashboard menu
  "Refresh" (no restart needed).
- **Built-in / strategy dashboards**: generated by HA (Overview, Areas, Map,
  Energy, Lights, Climate, Security, Maintenance...). See "Strategies".

### YAML-mode dashboards (2026.2 form)

Top-level `lovelace: mode: yaml` was deprecated in 2026.2 (repair
`yaml_mode_deprecated`, announced for removal in 2026.8). Do not write it. Use:

```yaml
# configuration.yaml
lovelace:
  resource_mode: yaml              # only if resources (custom cards) are managed in YAML
  resources:
    - url: /local/my-card.js       # /config/www/my-card.js
      type: module
  dashboards:
    lovelace:                      # the key "lovelace" makes it the main dashboard
      mode: yaml
      filename: ui-lovelace.yaml
      title: Overview
      icon: mdi:view-dashboard
      show_in_sidebar: true
    wall-panel:                    # any other key must contain a hyphen
      mode: yaml
      filename: dashboards/wall-panel.yaml
      title: Wall panel
      require_admin: false
```

- `resource_mode: yaml` disables resource management in the UI. With the
  Marketplace / HACS on UI dashboards you normally leave it out.
- Reload resources with the `lovelace.reload_resources` action.
- Split large YAML dashboards with `!include`:

```yaml
# dashboards/wall-panel.yaml
title: Wall panel
views:
  - !include views/home.yaml
  - !include views/energy.yaml
```

## Sections view (the default)

New dashboards and the "Convert" button for old masonry views produce
`type: sections`. A sections view is a responsive grid of **sections**; each
section is a 12-column grid of cards.

How HA picks the view type: an explicit `type:` wins; `panel: true` → panel;
`sections:` present → sections; `cards:` present → **masonry**; nothing →
sections. Always write `type: sections`.

```yaml
views:
  - title: Home
    path: home                     # URL: /<dashboard>/home
    icon: mdi:home
    type: sections
    max_columns: 3                 # max sections side by side (default 4)
    dense_section_placement: true  # fill gaps with later sections
    background:                    # a map since 2025.1 (also size, alignment, repeat, attachment)
      image: /local/background.jpg
      opacity: 40
    header: {...}                  # 2025.3
    badges: [...]
    sections: [...]
    footer: {...}                  # 2026.3
```

Other view options: `subview: true` + `back_path:` (hidden from the tab bar,
shows a back arrow) and `visible:` (list of `{user: <id>}`).

### Sections

```yaml
sections:
  - type: grid                     # the only built-in section type
    column_span: 2                 # width in view columns (1-4), 2024.9
    theme: dark-section            # optional
    background:                    # tinted section, 2026.4
      color: blue
      opacity: 30
    visibility:
      - condition: screen
        media_query: "(min-width: 1024px)"
    cards:
      - type: heading
        heading: Living room
      - type: tile
        entity: light.sofa
  - strategy:                      # generated section, see Strategies
      type: common-controls
      limit: 8
```

- Start every section with a heading card. Section `title:` is deprecated
  (2024.10) and is migrated to a heading card automatically.
- Since 2026.4 the row gap is 24 px (it was 8 px). The theme variable
  `ha-view-sections-row-gap: 8px` restores the old spacing. Heading cards size
  to their content by default.
- 2026.11: sections can be copied and pasted; generated ones can be converted.

### grid_options (card size)

Each section is **12 columns** wide. Rows are 56 px plus gap.

```yaml
- type: tile
  entity: light.sofa
  grid_options:
    columns: 6        # 1-12 or "full"; 6 = half width
    rows: 1           # number or "auto" (2026.4: auto = fit content)
```

Full width is `12` (or `full`), half `6`, third `4`, quarter `3`.

Converting old configs: `layout_options: {grid_columns: N, grid_rows: R}` →
`grid_options: {columns: N*3, rows: R}`. `grid_columns: full` → `columns: full`.
Each card has a default and minimum size (tile: 6 x 1); the editor clamps to
those. Custom cards report sizes through `getGridOptions()` (the old
`getLayoutOptions()` is deprecated).

### View header (2025.3) and footer (2026.3)

```yaml
header:
  layout: responsive        # start | center | responsive
  badges_position: bottom   # bottom | top
  badges_wrap: scroll       # wrap | scroll (2025.5)
  card:
    type: markdown
    text_only: true
    content: "# Hello {{ user }}"
footer:                     # one sticky card at the bottom
  max_width: 600            # default 600 px
  card:
    type: tile
    entity: alarm_control_panel.home
```

## Badges

Badges were redesigned in 2024.8 and work in sections and masonry views. Old
string badges are converted to `{type: entity, entity: ..., show_name: true}`.

```yaml
badges:
  - type: entity                   # default type
    entity: sensor.outdoor_temp
    name: Outside
    show_name: false               # show_icon / show_state default true
    state_content:                 # what to show as the state text
      - state
      - last_changed
    color: orange
    visibility:
      - condition: numeric_state
        entity: sensor.outdoor_temp
        below: 3
  - type: shortcut                 # 2026.5
    text: Good night               # the shortcut *card* uses `label:` instead
    tap_action:
      action: perform-action
      perform_action: script.good_night
  - type: alert                    # 2026.11; also alert_color, clear_color
    entity: binary_sensor.smoke
    pulse: true
```

Badge types: `entity`, `shortcut`, `alert` (2026.11), `entity-filter`, and the
energy badges `power-total`, `gas-total`, `water-total`. `state-label` is the
legacy badge. `display_type` (2024.8) was replaced by `show_name` /
`show_state` / `show_icon` in 2024.9. Badges also take `time_format` (2026.7).

## Heading card (2024.10)

Titles a section and carries small badges and buttons.

```yaml
type: heading
heading: Kitchen
heading_style: title               # title | subtitle
icon: mdi:fridge
tap_action:
  action: navigate
  navigation_path: /home/kitchen
badges:
  - type: entity
    entity: sensor.kitchen_temperature
    color: state
  - type: button                   # 2026.2
    icon: mdi:lightbulb-off
    text: All off
    color: amber
    tap_action:
      action: perform-action
      perform_action: light.turn_off
      target:
        area_id: kitchen
```

Heading badges also take `visibility:`. `entities:` on the heading card is
deprecated: use `badges:`.

## Tile card

The default card for one entity. Use it before reaching for Mushroom.

```yaml
type: tile
entity: climate.living
name: Heating                      # string or name objects
icon: mdi:radiator
color: deep-orange                 # state | none | theme color name | hex
# also: show_entity_picture, vertical, hide_state (all default false)
state_content:
  - state
  - current_temperature
tap_action: {action: more-info}
icon_tap_action: {action: toggle}
features_position: bottom          # bottom | inline (2025.3)
features:
  - type: climate-hvac-modes
    style: icons                   # many features: icons | dropdown
    hvac_modes: [heat, cool, "off"]
  - type: target-temperature
  - type: trend-graph
    hours_to_show: 24
grid_options:
  columns: 12
```

With `features_position: inline` the first feature sits next to the name; since
2026.9 the remaining features go below in two columns. For timestamp sensors,
`time_format:` takes `relative`, `total`, `date`, `time` or `datetime`.

| Domain | Feature types |
|---|---|
| Alarm | `alarm-modes` |
| Climate | `climate-hvac-modes`, `climate-fan-modes`, `climate-preset-modes`, `climate-swing-modes`, `climate-swing-horizontal-modes`, `target-temperature`, `target-humidity` |
| Cover | `cover-open-close`, `cover-position`, `cover-tilt`, `cover-tilt-position`, `cover-position-favorite`, `cover-tilt-favorite` (2026.4) |
| Fan | `fan-speed`, `fan-preset-modes`, `fan-direction`, `fan-oscillate` (2025.9) |
| Light | `light-brightness`, `light-color-temp`, `light-color-favorites` (2026.4), `light-effect` (2026.9), `light-color` (2026.11) |
| Lock | `lock-commands`, `lock-open-door` |
| Media player | `media-player-playback` (2025.9, `controls:` list 2026.5), `media-player-volume-slider` (2025.1), `media-player-volume-buttons`, `media-player-source`, `media-player-sound-mode` (2026.5) |
| Weather | `temperature-forecast`, `precipitation-forecast` (2026.6) |
| Timer | `timer-actions`, `timer-presets` (2026.10) |
| Humidifier | `humidifier-modes`, `humidifier-toggle` |
| Vacuum / mower | `vacuum-commands`, `vacuum-fan-speed`, `lawn-mower-commands` |

## Other built-in cards

| Card | Use for |
|---|---|
| `tile` | one entity with controls (default choice) |
| `heading` | section title with badges/buttons |
| `area` | one area: picture/camera, sensors, area-controls |
| `entities` | a list of rows (settings, many sensors) |
| `glance`, `button`, `entity` | compact entity displays (older; tile usually better) |
| `shortcut` | a labelled button that navigates or runs an action (2026.5) |
| `alert` | one problem entity with alert/clear colors and pulse (documented and in the editor from 2026.11) |
| `clock` | digital or analog clock (2025.4) |
| `date` | today's date (2026.11) |
| `distribution` | split of entities sharing a device class, e.g. power per appliance (2026.2) |
| `gauge` | one numeric value with severity bands (redesigned 2026.4) |
| `sensor`, `history-graph`, `statistics-graph`, `statistic` | values and graphs over time |
| `markdown` | text with templates; takes actions since 2026.4 |
| `map`, `logbook`, `calendar`, `todo-list`, `shopping-list` | as named |
| `media-control`, `thermostat`, `humidifier`, `light`, `alarm-panel` | big single-domain controls |
| `picture`, `picture-entity`, `picture-glance`, `picture-elements` | images, camera views, floor plans |
| `weather-forecast`, `plant-status` | as named |
| `iframe` | embed a web page (shown as "Webpage" in the UI; there is no `type: webpage`) |
| `conditional`, `entity-filter` | show a card / filter a list by conditions |
| `grid`, `horizontal-stack`, `vertical-stack` | grouping inside one card slot (rarely needed in sections) |
| `energy-*`, `power-sankey`, `power-sources-graph`, `water-sankey`, `water-flow-sankey`, `energy-compare` | energy dashboard cards (sankeys 2025.8 / 2025.12) |

### Snippets for the newer cards

```yaml
- type: clock
  clock_style: analog              # digital | analog
  clock_size: medium               # small | medium | large
  time_format: "24"                # "12" | "24"
  show_seconds: false
  time_zone: Europe/Madrid
  date_format: medium              # 2026.8: short | medium | long | full | iso, or a list of parts

- type: date                       # 2026.11
  date_format: long
  date_size: large

- type: shortcut                   # 2026.5; also description, color
  label: Garage
  icon: mdi:garage
  tap_action: {action: navigate, navigation_path: /home/garage}

- type: alert                      # documented from 2026.11
  entity: binary_sensor.water_leak
  alert_color: red
  clear_color: green
  pulse: true

- type: area                       # redesigned 2025.7
  area: kitchen
  display_type: picture            # compact | icon | picture | camera
  tap_action: {action: navigate, navigation_path: /home/kitchen}
  features:
    - type: area-controls
      controls:
        - light
        - fan
        - entity_id: switch.coffee_machine

- type: logbook
  target:                          # replaces entities:, 2025.1
    area_id: hallway
  hours_to_show: 12

- type: map                        # vector map since 2026.10
  entities:
    - person.ana
    - entity: device_tracker.car
      label_mode: name             # name | state | attribute | icon
  fit_zones: true
  cluster: true
```

The map card's `theme_mode` and `map_style` options exist since 2026.10; check
the allowed `map_style` values in the editor before writing them.

## Visibility conditions

`visibility:` works on cards (2024.6), sections and badges. All conditions must
pass (AND). The `conditional` card and `entity-filter` use the same conditions.

```yaml
visibility:
  - condition: state
    entity: binary_sensor.door
    state: "on"                    # or state_not:
  - condition: numeric_state
    entity: climate.living
    attribute: current_temperature # attribute: since 2026.5
    above: 25
  - condition: screen
    media_query: "(min-width: 1024px)"
  - condition: user
    users:
      - 581fca7fdc014b8b894519cc531f9a04   # user id, not the name
  - condition: or
    conditions:
      - {condition: state, entity: person.ana, state: home}
      - {condition: state, entity: person.luis, state: home}
  - condition: not
    conditions:
      - {condition: state, entity: input_boolean.guest_mode, state: "on"}
  - condition: time
    after: "07:00"
    before: "23:00"
    weekdays: [mon, tue, wed, thu, fri]
```

- `and`, `or`, `not` take a `conditions:` list.
- Since 2026.10 automation conditions work too: `template`, `sun`, `zone`,
  `device` and integration conditions. The UI now saves `entity_id:` for
  state/numeric_state; `entity:` still works.
- 2026.11: `location` also takes `target`, `match_mode: any_zone | active_zone`
  and `away`.
- User ids: Settings > People > Users (advanced mode).

## Actions

Cards, badges, heading badges, rows and features accept `tap_action`,
`hold_action`, `double_tap_action`; tiles and some others add
`icon_tap_action` / `icon_hold_action` / `icon_double_tap_action`.

```yaml
tap_action:
  action: perform-action
  perform_action: light.turn_on
  target:
    entity_id: light.sofa          # or area_id / device_id / floor_id / label_id
  data:
    brightness_pct: 50
  confirmation:
    text: Turn on the sofa lamp?
    exemptions:
      - user: 581fca7fdc014b8b894519cc531f9a04
```

| `action` | Extra keys |
|---|---|
| `more-info` | `entity` (optional, another entity) |
| `toggle` | none |
| `perform-action` | `perform_action` (required), `data`, `target` |
| `navigate` | `navigation_path` (required), `navigation_replace` |
| `url` | `url_path` (required) |
| `assist` | `pipeline_id`, `start_listening` |
| `fire-dom-event` | anything (for browser_mod and similar) |
| `none` | none |

`call-service`, `service:` and `service_data:` were deprecated in 2024.8. HA
2026.11 still runs them, but write the new form. Any HA action works in
`perform_action`, including `script.<name>`, `scene.turn_on`, `button.press`.

## Names

Since 2025.11 `name:` on cards, badges and rows is a string or one or more
name objects:

```yaml
- type: tile
  entity: light.sofa_lamp
  name: Sofa lamp                  # fixed text
- type: tile
  entity: light.sofa_lamp
  name: {type: device}             # one object: entity | device | area | floor | text
- type: tile
  entity: light.sofa_lamp
  name:                            # several, joined: "Living room Lamp (east)"
    - type: area
    - type: entity
    - {type: text, text: "(east)"}
```

**2026.11, backward-incompatible:** cards, badges and rows without `name:` show
"Device name + entity name" instead of the entity's `friendly_name`. Check
dashboards that relied on friendly names, and set `name:` (often
`{type: entity}` inside a room section). In templates, `friendly_name` is
slated for deprecation; use `entity_name()`, `device_name()`, `area_name()`.

## Colors

`state_color` is being replaced by `color:`:

Values: `state` (follow the entity state color), `none`, a theme color name
(`primary`, `accent`, `red`, `pink`, `purple`, `indigo`, `blue`, `light-blue`,
`cyan`, `teal`, `green`, `lime`, `yellow`, `amber`, `orange`, `deep-orange`,
`brown`, `grey`, `blue-grey`, ...) or a hex string such as `"#ff9800"`.

Tiles and badges take `color:`. The button card has it since 2025.11; entities
and glance cards were migrated later. `state_color` still works where it
exists. History and statistics graphs take a per-entity `color` (2026.6), and
the sensor card takes `color` in 2026.11.

## Strategies and built-in dashboards

A strategy generates a dashboard, view or section at runtime, so it follows new
devices automatically. "Take control" (dashboards) and "Convert to manual
section" (sections) turn them into normal config.

| Level | Strategy types |
|---|---|
| Dashboard | `original-states` (Overview legacy), `home` (Overview), `areas`, `map`, `iframe`, `energy` |
| View | `original-states`, `energy`, `water`, `gas`, `power`, `map`, `area`, `areas-overview`, `home-*`, `light`, `security`, `climate`, `maintenance` |
| Section | `common-controls` (2025.10), `device`, `entities` (2026.11) |

Built-in dashboards: Map and Webpage (2024.4; Webpage replaces `iframe_panel`),
Areas (2025.4, experimental), Home (2025.9), Lights, Climate and Security
(2025.11), Maintenance (2026.5). Since 2025.12 an admin sets the system-wide
default dashboard and each user can override it. In 2026.2 Home became
**Overview**, the default for new installs; the old auto-generated dashboard
is "Overview (legacy)" (`original-states`). Since 2026.5 custom dashboard
strategies can be registered.

```yaml
sections:
  - strategy:
      type: common-controls        # most used entities, from usage prediction
      limit: 8
      exclude_entities: [switch.server]
      heading:                     # replaces the deprecated title/icon
        type: heading
        heading: Quick controls
  - strategy:
      type: device                 # all entities of one device
      device_id: 3f2a9c8e5b1d4e6f8a7b6c5d4e3f2a1b
      display: tiles               # tiles | list
      categories: [control, sensor]   # also event, config, diagnostic
      heading: device              # device | area | none
  - strategy:
      type: entities               # entities matching a target and types
      title: Ground floor lights
      entity_types: [light]
      target:
        floor_id: ground_floor
```

A whole dashboard from a strategy (UI raw editor or YAML file):

```yaml
strategy:
  type: areas
```

## Themes

```yaml
# configuration.yaml
frontend:
  themes: !include_dir_merge_named themes
```

```yaml
# themes/midnight.yaml
midnight:
  primary-color: "#5c6bc0"
  accent-color: "#ff7043"
  card-background-color: "#1e1e2e"
  ha-card-border-radius: 16px
  ha-view-sections-row-gap: 8px        # 2026.4: restore the old 8 px gap
  ha-section-background-color: "#25253a"
  ha-section-border-radius: 20px
```

- 2025.5 removed all `paper-*` variables (`--paper-item-icon-color`,
  `--paper-font-*`...). Typography uses `--ha-font-family-body`,
  `--ha-font-size-*`, `--ha-font-weight-*`, `--ha-line-height-*`. Old themes
  that set `paper-*` keys do nothing.
- 2026.2: the default theme dropped the blue top bar; users pick a theme in
  their profile. Theme variables for the header after that change are not
  verified here; inspect the element before writing them.
- `theme:` works per view, per section and on many cards. Reload with
  `frontend.reload_themes`.

## Custom cards

Since **2026.11** HACS is built in as the **Marketplace** (Settings >
Marketplace) for cards, themes and integrations. On older versions install
HACS. Since 2026.6 the card picker has a "By entity" tab that also lists
custom cards that provide suggestions.

Check built-ins first: tile features, badges, heading, shortcut, clock, date,
distribution, alert, visibility and sections cover most of what Mushroom,
layout-card, mini-graph-card and button-card were installed for. Custom cards
are still fine when needed; use current syntax with them too (`perform-action`,
`grid_options`). Current versions: Mushroom 5.2.3 (2026-09), card-mod 4.2.1,
button-card 7.0.1 (7.1.0 in development).

```yaml
# button-card: needs section_mode: true to follow grid_options in sections.
- type: custom:button-card
  section_mode: true
  entity: scene.movie
  name: Movie
  icon: mdi:movie-open
  grid_options:
    columns: 6
    rows: 2
  tap_action:
    action: perform-action
    perform_action: scene.turn_on
    target:
      entity_id: scene.movie

# card-mod 4: CSS on a built-in card. Use --ha-* variables.
- type: tile
  entity: binary_sensor.smoke
  card_mod:
    style: |
      ha-card {
        {% if is_state(config.entity, 'on') %}
        border: 2px solid var(--error-color);
        {% endif %}
      }
```

- Mushroom 5 rebuilt `custom:mushroom-template-card` on the tile card: it takes
  `color` (not `icon_color`) and tile `features:`. The old card is
  `custom:mushroom-legacy-template-card`.
- `button_card_templates:` goes at the top level of the dashboard, next to
  `views:`.
- For rows inside an entities card, put `card_mod` on the row and target
  `:host`.
- A custom card that ignores the section grid probably does not implement
  `getGridOptions()`. Check its docs for a sections option (button-card:
  `section_mode: true`).

## Legacy layouts (to read or convert old configs)

- **Masonry** (`type: masonry`, or `cards:` without type): columns of cards
  placed by height. Edit the view and use "Convert" to get sections.
- **Panel** (`type: panel`): one card at full size; still right for a single
  map or floor plan. **Sidebar** (`type: sidebar`): cards set
  `view_layout: {position: sidebar}`.
- **Stacks, grid card, conditional card**: still valid. In sections views use
  separate cards with `grid_options` and `visibility:` instead.

## Examples and validator

- `examples/lovelace-dashboard.yaml`: three sections views using everything above.
- `examples/lovelace-custom-cards.yaml`: custom cards with current syntax, each
  next to the built-in card that replaces it.
- `scripts/lovelace_validator.py` flags the "Outdated" column of the table at
  the top (with line and release), missing `type`, actions without their
  required key, conditional cards without `conditions`, unknown card / badge /
  feature types and bad entity ids. Templates and `!include` values are skipped.
